# Гигиена рабочих веток

Обычный жизненный цикл эфемерной рабочей ветки в `repo-guard`:

```text
branch -> PR -> merge -> branch deletion
```

Этот цикл относится только к обычным рабочим веткам. Отсутствие открытого PR само по себе никогда не означает, что ветку можно удалить.

## Классификация

Модуль анализа гигиены веток использует слой фактов репозитория, чтобы различать:

- постоянные ветки: ветка по умолчанию и явно настроенные исключения;
- активные головы PR того же репозитория;
- принадлежащие живой или возобновляемой работе pre-PR ветки, если переданы валидные внешние данные владения;
- кандидаты в сироты, которым требуется отдельная сверка;
- остаточные головы уже объединённых PR;
- отклонение настройки `delete_branch_on_merge`.

Явно постоянные ветки должны задаваться входными данными анализа. Удобное имя ветки, возраст, отставание от `main` или отсутствие PR не создают постоянного исключения автоматически.

## Безопасность удаления

Автоматическое удаление допустимо только для точной головы уже объединённого PR того же репозитория. Перед удалением доверенный путь должен заново проверить, что:

1. текущий идентификатор коммита ветки совпадает с ожидаемым идентификатором головы объединённого PR;
2. ветка не является веткой по умолчанию или явно постоянной;
3. ветка не используется текущим открытым PR;
4. PR действительно объединён;
5. запрос относится к тому же репозиторию, а не к голове fork-PR.

Если идентификатор коммита изменился после сбора доказательств, удаление запрещается. Код PR не должен иметь возможность выбрать произвольную ссылку для удаления.

## Pre-PR ветки

Ветка без PR может содержать единственное полезное незавершённое состояние. Поэтому диагностика может пометить её кандидатом в сироты, но не должна удалять её только по отсутствию PR, имени, возрасту, пересечению файлов или отношению предка.

Если внешний управляющий контур передаёт данные о долговременном владении, валидная живая или возобновляемая принадлежность сохраняет ветку. Невалидные переданные данные владения обрабатываются с запретом по умолчанию.

## Публичная граница

Текущий публичный CLI `repo-guard` не предоставляет отдельный режим управления ветками. Анализ гигиены веток остаётся самостоятельным внутренним слоем и не является частью команд `doctor`, `check-pr` или `init`.

Исторический накопленный набор веток не следует массово удалять на основании одной диагностики. Его нужно отдельно сверить с текущими PR, точными идентификаторами коммитов и данными о долговременном владении, после чего удалять только ветки с независимым доказательством завершённости или явного отказа от работы.
