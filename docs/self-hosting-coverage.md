# Покрытие самопроверкой

`repo-guard` рассматривает самоприменение как проверяемый инвариант, но больше не хранит полную ручную копию списка возможностей.

Нормальный inventory **выводится из кода**:

- команды — из `COMMANDS` в `src/repo-guard.mjs`;
- семейства правил — из `defaultRuleFamilies`;
- встроенные профили — из `listBuiltInProfiles()`;
- тесты — автоматическим discovery `tests/run.mjs`.

Файл [`self-hosting-coverage.json`](self-hosting-coverage.json) хранит только исключения: возможности, которые нельзя честно применить к самому инструментальному репозиторию. Каждое исключение обязано иметь содержательное объяснение. Удалённая или переименованная возможность не должна оставлять устаревшее исключение.

`tests/test-self-hosting.mjs` сопоставляет вычисленный inventory с собственной policy/CI и исключениями. Поэтому добавление обычной команды, rule family, профиля или тестового файла не требует синхронно дописывать ещё одну полную capability matrix.

Отдельно `markdown_language` применяется к документным поверхностям `Markdown`; тестовые fixtures остаются вне этой области, поскольку моделируют входные данные внешних репозиториев.
