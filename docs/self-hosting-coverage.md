# Покрытие самопроверкой

`repo-guard` рассматривает самоприменение как проверяемый инвариант, но не хранит полную ручную копию списка возможностей.

Нормальный inventory **выводится из кода**:

- команды — из реестра CLI;
- оставшиеся runtime families — из `defaultRuleFamilies`;
- policy packs — из реестра встроенных профилей;
- тесты — автоматическим discovery `tests/run.mjs`.

Основная семантика после Compression 2.0 сосредоточена в `Constraint Program`; сокращение числа runtime families не должно требовать ручного переписывания capability matrix.

Файл [`self-hosting-coverage.json`](self-hosting-coverage.json) хранит только реальные исключения: возможности, которые нельзя честно применить к инструментальному репозиторию. Каждое исключение обязано иметь объяснение. Удалённая, переименованная или превращённая в общий primitive возможность не должна оставлять stale exception.

`tests/test-self-hosting.mjs` сопоставляет вычисленный inventory с собственной политикой, CI и исключениями. Поэтому добавление обычного теста, команды или data-driven pack не требует синхронно поддерживать ещё один ручной список.

`markdown_language` применяется к документным Markdown-поверхностям; test fixtures остаются вне этой области, потому что моделируют внешние входные данные.

Core-freeze распространяется и на self-hosting: новая capability не должна создавать отдельный механизм только ради того, чтобы её можно было перечислить в матрице. Нормальное состояние выводится, вручную фиксируются только исключения.
