# Покрытие самопроверкой

`repo-guard` рассматривает самоприменение как проверяемый инвариант, но не хранит полную ручную копию списка возможностей.

Нормальный состав возможностей **выводится из кода**:

- команды — из реестра командной строки;
- оставшиеся семейства исполнения — из `defaultRuleFamilies`;
- пакеты политики — из реестра встроенных профилей;
- тесты — автоматическим обнаружением через `tests/run.mjs`.

Основная семантика после второй программы сжатия сосредоточена в `Constraint Program`; сокращение числа семейств исполнения не должно требовать ручного переписывания матрицы возможностей.

Файл [`self-hosting-coverage.json`](self-hosting-coverage.json) хранит только реальные исключения: возможности, которые нельзя честно применить к инструментальному репозиторию. Каждое исключение обязано иметь объяснение. Удалённая, переименованная или превращённая в общий примитив возможность не должна оставлять устаревшее исключение.

`tests/test-self-hosting.mjs` сопоставляет вычисленный состав возможностей с собственной политикой, CI и исключениями. Поэтому добавление обычного теста, команды или пакета данных не требует синхронно поддерживать ещё один ручной список.

`markdown_language` применяется к документным поверхностям Markdown; тестовые входные примеры остаются вне этой области, потому что моделируют данные внешних репозиториев.

Заморозка ядра распространяется и на самопроверку: новая возможность не должна создавать отдельный механизм только ради того, чтобы её можно было перечислить в матрице. Нормальное состояние выводится, вручную фиксируются только исключения.
