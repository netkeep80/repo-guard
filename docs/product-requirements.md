# Требования продукта RepoGuard

Нормативная authority хранится в отдельных файлах `requirements/repo-guard/RG-*.rg.yaml`. Этот документ — читаемое описание текущего продукта; при расхождении канонический Requirement имеет приоритет.

## Назначение

RepoGuard — небольшой детерминированный локальный causal compiler для проверки изменений репозитория по точным Git-снимкам.

```text
Snapshot
+ SubjectRef
+ Requirement
+ Relation
+ Constraint
+ Projection
```

Каноническая команда:

```bash
repo-guard check --base <sha> --head <sha>
```

Она не требует отдельного сетевого control plane. Обычный CI исполняет предметные тесты и доказательства, а платформа управляет review, required checks и правом merge.

## Что проверяет compiler

- **J2 — Requirement closure:** нормативный Requirement должен иметь допустимое rooted происхождение; замкнутый цикл сам себя не авторизует.
- **J1 — Resource closure:** каждый tracked Resource должен иметь причинное обоснование через версионированные отношения; orphan Resource остаётся RED.
- **J3 — transition cause:** изменение между точными `BASE/HEAD` должно иметь объяснимую причину в модели перехода.
- **Constraints:** ограничение действует в области конкретного Requirement и объявленных им отношений.
- **Projection:** производные документы и артефакты проверяются на freshness, ownership и точную identity источников/результата.

`repo-guard build` материализует только явно принадлежащие Projection файлы или owned regions. Authored bytes вне owned regions сохраняются.

## Требования RG-01…RG-08

| ID | Смысл |
| --- | --- |
| **RG-01** | Один и тот же exact `BASE/HEAD` и те же версионированные входы дают один и тот же semantic verdict. |
| **RG-02** | Принятие, текущее состояние и публикация не выводятся автоматически из CI или merge. |
| **RG-03** | Причинная область изменения ограничена явными Relations; несвязанный Resource не получает оправдание по соседству. |
| **RG-04** | Свидетельство не может доказывать больше, чем реально проверено; traceability не заменяет выполнение domain test/proof. |
| **RG-05** | Внешняя семантика и артефакты привязываются к точной принятой identity, а не к плавающей ссылке. |
| **RG-06** | Подключение явно фиксирует версию и exact `BASE/HEAD`; инструмент не обещает защиту, которой не наблюдает. |
| **RG-07** | Проверка принадлежит правильному владельцу: domain truth — предметному CI, merge authority — платформе, causal closure — RepoGuard. |
| **RG-08** | Новая публичная возможность появляется только из реального falsifier; равная гарантия при меньшей сложности предпочтительнее. |

## Границы

RepoGuard не является предметным prover и не определяет научную, бизнес- или продуктовую истинность. Он проверяет структуру причин, identity, отношения, constraints и projections.

Requirement identity не равна пути файла: стабильный `RequirementId` является identity, а путь — представлением. Документы и registries могут быть производными представлениями, но не должны становиться вторым нормативным источником.

Новая generic семантика добавляется только когда реальный consumer показывает случай, который нельзя выразить текущими Requirement/Relation/Constraint/Projection primitives. Исторические реализации остаются доступными через Git history и не должны поддерживаться как параллельный runtime текущего продукта.
