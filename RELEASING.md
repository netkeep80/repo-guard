# Выпуск новой версии

Этот документ описывает выпуск `repo-guard`, после которого потребители могут закрепиться за воспроизводимой версией.

## Версионирование

`repo-guard` использует [семантическое версионирование](https://semver.org/):

- **исправление** (`x.y.Z`) — исправления ошибок без изменения интерфейсов;
- **минорная версия** (`x.Y.0`) — обратно совместимые возможности;
- **мажорная версия** (`X.0.0`) — несовместимые изменения CLI, схемы политики или машинного результата.

## Инвариант выпуска

`package.json.version` определяет ссылку на `Action`, которую создаёт `repo-guard init`: `netkeep80/repo-guard@v<version>`.

Для каждой публикуемой версии пакета заранее должны существовать соответствующие тег и выпуск на `GitHub`:

```text
package.json.version = X.Y.Z
Git tag/release       = vX.Y.Z
Generated Action ref  = netkeep80/repo-guard@vX.Y.Z
```

До публикации проверьте инвариант:

```bash
npm run verify:release-ref -- --tag vX.Y.Z
```

`npm publish` запускает ту же проверку через `prepublishOnly`. Рабочий процесс проверки целостности выпуска повторяет её при публикации выпуска на `GitHub`.

## Последовательность выпуска

1. Убедитесь, что ветка `main` зелёная и обязательные проверки CI завершились успешно.
2. Обновите версию:

   ```bash
   npm version patch
   # либо minor / major
   ```

3. Отправьте коммит и тег:

   ```bash
   git push origin main --follow-tags
   ```

4. Создайте и опубликуйте выпуск на `GitHub` из отправленного тега.
5. Повторно проверьте ссылку выпуска:

   ```bash
   npm run verify:release-ref -- --tag v1.0.1
   ```

6. Опубликуйте пакет:

   ```bash
   npm publish
   ```

Поле `files` в `package.json` определяет содержимое публикуемого пакета.

## Проверка опубликованного пакета

После публикации можно повторить локальную дымовую проверку:

```bash
npm pack
TARBALL=$(ls repo-guard-*.tgz)
TMPDIR=$(mktemp -d)
npm install --prefix "$TMPDIR" "$PWD/$TARBALL"
"$TMPDIR/node_modules/.bin/repo-guard" --repo-root "$PWD"
```

Та же идея используется в CI для проверки устанавливаемого артефакта.

## Закрепление версии у потребителей

Потребитель должен использовать конкретную опубликованную версию:

```bash
npm install -g repo-guard@1.0.0
npx repo-guard@1.0.0
```

В `GitHub Actions`:

```yaml
- run: npx repo-guard@1.0.0
```

Не закрепляйте производственную проверку за изменяемой веткой, если требуется воспроизводимость.
